## C1 — NEW proposed wire contract and admission

This section specifies a NEW API, not an available BB/native API. Names and payloads are proposals requiring independent approval and later source/SDK gates.

Capability issuance/provisioning and native endpoint identity remain gated, not solved here.

Validate fixture schema/expiry/UID/private mode/type/no-symlink/canonical binding and canonical C equality to BOTH admitted fixture C and authoritative native owner C. Do not use process.cwd() or client C as the owner authority. No materializing view/history accessor may be called for admission. Root permits AT MOST ONE existing cached `host.view.current()` call per metadata operation, reading authoritative C ONLY from `cache.session.cwd`; never use a new materialization or Harness lookup. See C3 for operation-specific cache reads. Server without an admitted fixture permit rejects catalog mode. Proposed success uses existing envelope `{type:"response", id, command:"catalog-v1", success:true, data:{version:1}}`; no cwd/session/owner identity echo. Errors use the same envelope with success:false and a bounded constant error category; never raw exceptions/paths/capability values.

Per connection, extend only existing protocol admission flags with an exclusive catalog-mode flag; no competing execution state machine. Catalog handshake on a fresh connection selects catalog mode once. Normal attach selects the existing attached path. Neither mode can cross into the other; duplicate handshake, attached→catalog and catalog→attach fail. Preserve existing normal attach/commands/replay semantics, including its existing repeated-attach rejection. Catalog extension is disabled without explicit private-fixture admission.
